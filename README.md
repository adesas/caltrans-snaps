# caltrans-snaps 📷🚗

Continuous local recording of Caltrans traffic cameras into a rolling
**72-hour HLS archive**, with a GitHub Pages front-end. Starting region:
the **SR-70 corridor + SR-99 (Oroville · Yuba City · Marysville)** — an area
no public traffic-cam archive covers yet.

Architecture credit: the recorder pattern (ffmpeg copy-mode segments,
auto-reconnect on Caltrans's periodic 404s) and the Caltrans **ArcGIS CCTV
API** data source were inspired by
[Freeway-Snapshot/traffic-camera-archive](https://github.com/Freeway-Snapshot/traffic-camera-archive)
(an S3/AWS-oriented project without a license — this is an independent
implementation retargeted at local storage + Cloudflare Tunnel serving).

## How it works

```
Caltrans HLS feeds ──► src/snaps (1 ffmpeg per camera, copy-mode, no transcoding)
                          │  one session per clock hour → seekable HLS playlist
                          ▼
        /mnt/8tb/caltrans-snaps/hls/<camera>/<YYYY-MM-DD>/<HH>/
            index.m3u8 · a0_000.ts … · thumb.jpg      (+ status/ heartbeats)
                          │
   Caddy file_server :8090 ──► Cloudflare Tunnel (no open ports, free HTTPS)
                          │
        GitHub Pages site (web/): county/camera picker, day+hour scrubber,
                                  "Request a county" → GitHub Issue
```

- Caltrans feeds 404 every ~20–30 min (normal). The recorder restarts with
  capped backoff and **appends** new segments to the hour's playlist
  (`append_list`, per-attempt segment prefix) so mid-hour drops don't clobber
  earlier footage. Gaps in the archive = downtime only.
- A retention thread deletes hour-directories older than `retention_hours`.

## Current camera set (10)

| Route | Cameras |
|---|---|
| SR-70 | Feather River · Saddleback · Ramirez (Yuba) · Cox Ln/wo Oroville (Butte) |
| SR-99 | Riego NB (Sutter) · Hwy 162/Oroville · Neal/Durham · Southgate 1&2 · Skyway 1 (Chico) |

Regenerate/expand anytime (selection = route preference, distance from an
anchor, demotions, explicit include/exclude):

```bash
make catalog          # or python -m snaps.catalog --help
# grow to all of the 4 counties later:
PYTHONPATH=src python3 -m snaps.catalog --counties Butte Yuba Sutter Sacramento \
  --near 39.5124,-121.5417 --prefer-route SR-70 --limit 147 ... && git commit
```

`hls_url` patterns are stable; a daily catalog refresh is optional
(`url_refresh_hours`). Stream health: two Yuba feeds (Feather River,
Saddleback) were 404 at testing time — they self-heal via retries; watch
`status/*.json`.

## Storage / bandwidth budget (measured on this machine)

Measured per-camera: **~300–450 kbps**, 720×480 H.264 → **~4.3 GB/camera/day**.

| Scope | /day | 3 days | fits in 6.8 TB free? |
|---|---|---|---|
| 10 cams (today) | ~43 GB | **~130 GB** | trivially |
| all 147 cams, 4 counties | ~630 GB | ~1.9 TB | yes (~28% of free) |
Disk write load ~5 MB/s, RAM ~80 MB/ffmpeg proc — nothing on this box is a
constraint (16 cores / 46 GB).

**Bandwidth:** 10 cams ≈ 4 Mbps sustained; 147 ≈ **~60 Mbps (~19 TB/month)** —
check your ISP cap before scaling out.

**Caltrans policy note:** their conditions of use flag "bulk streaming (10+
simultaneous) requires written agreement". At 10 you're borderline-by-design;
if you scale to counties-wide coverage, consider emailing Caltrans District 3
for blessing.

## Run it

```bash
# one-off recording session (foreground):
make run                     # writes to storage_root in config/cameras.yaml

# permanent service:
sudo apt install caddy       # file server for HLS
make install-service         # systemd unit: caltrans-snaps
systemctl status caltrans-snaps

# serving via Cloudflare (no router ports opened):
cloudflared tunnel create caltrans-media
#   → deploy/cloudflared-config.example.yml + deploy/Caddyfile
caddy run --config deploy/Caddyfile &
cloudflared tunnel --config /etc/cloudflared/config.yml run &
```

## Website (GitHub Pages)

1. Create the GitHub repo, push, enable Pages (**Actions** deploy on every
   `web/**` push — see `.github/workflows/pages.yml`).
2. Edit `web/config.js`: set `MEDIA_BASE` to your tunnel hostname
   (e.g. `https://media.example.com`) and `REPO` to `you/caltrans-snaps`.
3. The site reads `web/cameras.json` (generated by `make catalog`), shows a
   camera rail with live thumbnails, a day + hour scrubber (green = recorded),
   and an hls.js player. **Request a county** opens a prefilled GitHub Issue —
   zero backend.
